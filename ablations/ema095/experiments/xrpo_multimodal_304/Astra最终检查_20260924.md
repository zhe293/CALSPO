## 算法核对与修复

此前 XRPO 是独立重写的 HARPO，含额外归一化差异、截断范围、历史任务参照和额外平滑，不能归因为用户提出的改动二、三。已备份并替换。

用户已明确选择：**以仓库原实现为共同基础**。

两组现在使用同一个 `core_algos.compute_harpo_outcome_advantage`：

- HARPO 默认路径保留原行为，`BETA_RHO = BETA_LOGMULT = 0.95`。
- XRPO 将上述两处设为 0.90；问题层仍使用原始计算，不增加平滑，不做幂次收缩。
- 保留原始任务标签 `depression_cls`、`emotion_cls`，不再擅自改为“任务×模态”。
- 改动三直接使用本批任务内的问题贡献代理几何均值：

```text
q_signal = max(mean(abs(A_GRPO_of_question)), 原实现eps)
R_task   = geometric_mean(本批该任务的q_signal)
R_global = geometric_mean(本批各任务的R_task)
x_task   = R_task / R_global
A_XRPO   = A_原HARPO(beta=0.90) × x_task
```

新增 x 不额外做 EMA、不新增截断、不做幂次收缩。原 HARPO 问题层和任务层原有的数值保护和截断保持不变。仓库问题层没有论文笔记所述的历史平滑，所以此处 `R_task` 使用原实现的当前问题贡献代理；这是用户选择的代码版本，不能再写成论文公式的完整复现。

算法测试使用真实仓库辅助函数：

1. 修改后默认路径与旧函数在连续多步输入上逐位相同。
2. 新增 x 与独立几何平均计算一致，分子分母正确；输出等于 beta=0.90 的 HARPO 输出乘 x。
3. 两处真实 EMA 更新均满足 `0.90×旧值 + 0.10×新值`，系数在对数空间平滑。
4. 单任务 x=1；全零优势仍为零；测试极端组时输出有限。

## 数据、批次与多模态

- 生效数据：`/data/datasets/human_behavior_atlas-data/changshaoqing_multimodal_304_v4`。
- 训练 304 条：80 文本、152 文本+音频、72 文本+视频+音频。
- 测试 64 条：16、32、16；保留抑郁分类，只修正不存在音频的文本题目。
- 两组均为奖励 B、seed=45、batch=8、每题 4 回答、38 步、回答上限 256 token。
- 原模态分批会让每批只有一个任务，使 x 恒为 1。两组改为相同 seed 的随机混合批次；单条生成/训练 microbatch 仍为 1。
- 已检查 38 批覆盖全部 304 条且不重复；34 批包含两个任务。其余 4 批的 x=1 是公式的正常退化。
- 全部 304+64 条通过真实解码、处理器及位置编码检查；训练最大有效 prompt 811 token，测试 755，均低于 896。
- 音频最长约 13.15 秒；视频使用 2 帧，属于资源受限的趋势实验。
- 数据集位置编码改为直接调用已安装 Omni 的实际位置计算方法，避免生成使用 Omni、训练使用 Qwen2-VL 的不一致。
- 真实 Omni 类的缩小随机模型对三种输入均完成 CPU 前向、反向，显式位置与模型自动位置的输出一致。这不能替代完整 3B FSDP GPU 验证。
